请基于当前 CRM 项目，实现 Spring Security 方法级授权的第一个最小验证。

【项目现状】
1. 已实现 JWT 认证、多角色权限聚合和 GrantedAuthority 转换。
2. 已修复权限 SQL 缺少角色逻辑删除过滤的问题。
3. 当前业务接口主要使用 authenticated()，尚未根据权限编码进行授权。

【角色设计】
SUPER_ADMIN：具有全部系统管理权限。
SYSTEM_ADMIN：具有受限的系统管理权限，只能管理普通业务角色及其权限。
SALES_MANAGER、SALES_STAFF：目前不授予系统管理操作权限。

SYSTEM_ADMIN 不能：
- 分配 SUPER_ADMIN 或 SYSTEM_ADMIN 角色。
- 编辑、停用、删除系统级角色或修改其权限。
- 给普通角色授予未经批准的权限。
- 通过修改自身账号或角色扩大权限。

注意：上述限制是后续对象级授权任务，本次不要实现，也不能声称本次完成了这些限制。

【本次开发目标】
只启用方法级安全，并为 POST /api/roles 增加 role:create 权限检查。

【第一步：检查】
1. 检查 SecurityConfig 当前配置。
2. 确认 RoleController 创建角色接口的真实路径和方法签名。
3. 确认 role:create 权限编码存在。
4. 检查现有测试结构。

【第二步：实现】
1. 在现有 SecurityConfig 中启用 @EnableMethodSecurity。
2. 在创建角色方法上添加：
   @PreAuthorize("hasAuthority('role:create')")
3. 保留原有 JWT、SecurityFilterChain 和业务逻辑。
4. 不新增 SUPER_ADMIN 绕过规则。
5. 不修改其他业务接口和前端。

【第三步：测试】
验证以下场景：
- 无 Token：401。
- 已认证但缺少 role:create：403。
- 已认证且拥有 role:create：通过授权检查。

有权限场景应隔离业务写入，避免创建真实角色。

优先复用现有测试结构；如需补充测试，仅增加与本次授权相关的最小测试。

执行相关测试及后端编译，报告真实结果。

【安全边界】
本次只实现功能级授权，不实现 SYSTEM_ADMIN 的对象级限制。

如果发现现有创建角色接口允许 SYSTEM_ADMIN 创建系统级角色，记录为待解决的越权风险，不要在本次扩大修改范围。

不得将本次实现描述为完整 RBAC 授权闭环。

不修改数据库结构和数据。
不重构认证体系。
不修改 JWT、SecurityUser、CustomUserDetailsService。
不修改其他 Controller。

1. 修改文件及代码。
