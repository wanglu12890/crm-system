基于当前 CRM 项目已有“角色权限回显 + 权限保存”功能，完善前后端的“权限集合是否真正发生变化”判断。

当前已有：

```text
新建角色                  ✅
权限树展示                ✅
权限回显                  ✅
权限保存                  ✅
权限变更检测优化           ← 本次
新建用户 + 绑定角色
权限控制差异
阶段测试
```

当前问题：

前端现在只要用户打开权限配置弹窗并点击“保存”，即使权限没有任何变化，也会调用：

```http
PUT /api/roles/{roleId}/permissions
```

后端随后执行：

```text
DELETE 旧权限关系
+
INSERT 新权限关系
```

这会产生无意义请求和数据库写操作。

还存在第二种情况：

```text
初始权限：
A B C

用户取消 C
→ 当前 A B
→ 保存按钮应该可用

用户随后又重新勾选 C
→ 当前重新变成 A B C
→ 与初始权限完全一致

此时保存按钮应该重新禁用
```

本次目标：

```text
前端：
比较“初始权限集合”和“当前权限集合”
↓
无变化 → 保存按钮禁用
有变化 → 保存按钮可用

后端：
即使收到请求
也再次比较数据库当前权限和提交权限
↓
完全一致 → 直接返回，不执行 DELETE / INSERT
有变化 → 执行完整替换
```

二、前端新增“初始权限集合”和“当前权限集合”

在 `RolePermissionDialog.vue` 中新增类似状态：

```ts
const initialPermissionIds = ref<string[]>([])
const currentPermissionIds = ref<string[]>([])
```

注意：

权限是“集合”，不是有顺序意义的数组。

例如：

```text
A B C
```

与：

```text
C A B
```

业务上完全相同。

因此不要直接使用：

```ts
JSON.stringify(a) === JSON.stringify(b)
```

进行比较。

三、回显完成后记录初始状态

当前打开流程大致是：

```text
加载权限树
↓
查询角色已有权限
↓
setCheckedKeys(permissionIds)
↓
完成回显
```

请调整为：

```text
加载权限树
↓
查询角色已有权限
↓
await nextTick()
↓
setCheckedKeys(permissionIds)
↓
await nextTick()
↓
从 treeRef.getCheckedKeys() 重新读取 Tree 最终实际 checked 状态
↓
同时初始化 initialPermissionIds 和 currentPermissionIds
```

推荐类似：

```ts
await nextTick()

treeRef.value?.setCheckedKeys(permissionIds)

await nextTick()

const checkedIds = (treeRef.value?.getCheckedKeys() ?? []).map(String)

initialPermissionIds.value = [...checkedIds]
currentPermissionIds.value = [...checkedIds]
```

为什么不能简单：

```ts
initialPermissionIds.value = permissionIds
```

因为当前：

```text
check-strictly = false
```

存在父子联动。

最终 Element Plus Tree 的 checkedKeys 才是用户实际看到和操作的真实状态。

四、监听用户权限选择变化

给 `<el-tree>` 增加或复用：

```vue
@check="handlePermissionCheck"
```

新增：

```ts
const handlePermissionCheck = () => {
  currentPermissionIds.value =
    (treeRef.value?.getCheckedKeys() ?? []).map(String)
}
```

如果当前已有 `@check` 事件，请合并逻辑，不要重复绑定。

每次用户：

```text
勾选权限
取消权限
勾选父节点
取消父节点
```

都更新 `currentPermissionIds`。

五、增加集合比较方法

实现一个明确的集合比较函数，例如：

```ts
const isSamePermissionSet = (a: string[], b: string[]) => {
  const setA = new Set(a)
  const setB = new Set(b)

  if (setA.size !== setB.size) {
    return false
  }

  return [...setA].every(id => setB.has(id))
}
```

需要考虑重复 ID，即集合语义。

六、增加 hasPermissionChanged

使用：

```ts
const hasPermissionChanged = computed(() => {
  return !isSamePermissionSet(
    initialPermissionIds.value,
    currentPermissionIds.value
  )
})
```

含义：

```text
false
→ 当前权限与打开弹窗时完全相同

true
→ 用户确实修改了权限
```

八、handleSave 增加防御判断

十一、后端增加幂等比较

```java

```

大致流程：

```text

```

请修改为：


十二、后端集合比较

权限顺序没有业务意义，因此必须用集合比较。

例如：

```text
数据库：
A B C

前端提交：
C A B
```

应该认定：

```text
完全相同
```

不能因为顺序不同执行写库。

推荐使用：

```java
Set<Long>
```

例如：

```java
Set<Long> requestedPermissionIds = new LinkedHashSet<>(permissionIds);
Set<Long> existingPermissionIds = new HashSet<>(...);
```

然后：

```java
if (existingPermissionIds.equals(requestedPermissionIds)) {
    return;
}
```

具体类型根据现有代码调整。
