====================
一、当前已确定业务规则
====================

角色职责：

SUPER_ADMIN：
- 系统根管理员。
- 负责角色创建、权限配置。
- 可以配置 SYSTEM_ADMIN、SALES_MANAGER、SALES_STAFF 以及未来自定义角色权限。
- 不允许修改 SUPER_ADMIN 自身权限。

SYSTEM_ADMIN：
- 负责日常用户管理。
- 可以创建用户并分配已有普通业务角色。
- 不负责角色创建。
- 不负责权限配置。
- 不允许查看完整权限树。

因此：

角色权限管理：

只有：
SUPER_ADMIN + role:assign_permission

才允许：
- 查看角色权限
- 修改角色权限


权限树：
只有：
SUPER_ADMIN + permission:list

才允许：
- 查看系统权限列表

====================
三、实现角色权限配置授权
====================

目标：

角色权限相关接口：

查看角色权限：
例如：
GET /api/roles/{id}/permission-ids


修改角色权限：
例如：
PUT /api/roles/{id}/permissions


统一增加：
只有：

ROLE_SUPER_ADMIN
+
role:assign_permission

才能访问。


推荐：

@PreAuthorize(
    "hasRole('SUPER_ADMIN') and hasAuthority('role:assign_permission')"
)


注意：
不要只依赖 role:assign_permission。

原因：

即使数据库错误地给 SYSTEM_ADMIN 分配了 role:assign_permission，
也不能让 SYSTEM_ADMIN 修改权限。


====================
四、实现禁止修改 SUPER_ADMIN 自身权限
====================

功能权限通过后，还需要 Service 层范围检查。

位置：

RoleServiceImpl.updateRolePermissions()

或者实际处理角色权限保存的方法。


规则：

如果目标角色：

roleCode = SUPER_ADMIN


则：

拒绝修改。


包括：

- 增加权限
- 删除权限
- 替换权限


返回：

HTTP 403


建议新增业务异常：

例如：

ForbiddenRolePermissionException


错误码：

ROLE_PERMISSION_UPDATE_FORBIDDEN


响应：

{
    "title": "角色权限修改失败",
    "status": 403,
    "code": "ROLE_PERMISSION_UPDATE_FORBIDDEN",
    "detail": "不允许修改 SUPER_ADMIN 自身权限"
}


不要返回：

数据库异常。
SQL异常。
堆栈信息。
