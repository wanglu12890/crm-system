五、permissionCount 的来源



需要特别注意：


```text
permissionCount
```



不是 \`sys\_role\` 表自身字段。



它表示：


```text
该角色当前关联的权限数量
```



数据来源：


```text
sys_role
      ↓ role_id
sys_role_permission
      ↓
COUNT(permission_id)
```



例如：


```text
SUPER_ADMIN
    ↓
sys_role_permission 中关联 10 条权限
    ↓
permissionCount = 10
```



如果某个角色没有分配任何权限：


```text
permissionCount = 0
```



而不是：


```text
null
```

\## 六、角色查询 SQL / Mapper 设计



优先根据当前项目 MyBatis-Plus 使用方式选择最简单、最符合现有风格的实现。



推荐优先考虑：


```text
一次查询直接得到角色基本信息 + permissionCount
```



避免：


```text
先查询全部角色
然后循环每个角色执行一次 COUNT SQL
```



不要产生明显的 N+1 查询。



可以考虑使用：


```sql
LEFT JOIN sys_role_permission
```



配合：


```sql
COUNT(...)
GROUP BY
```



例如逻辑上类似：


```sql
SELECT
    r.id,
    r.role_name,
    r.role_code,
    r.status,
    COUNT(rp.permission_id) AS permission_count,
    r.remark
FROM sys_role r
LEFT JOIN sys_role_permission rp
    ON r.id = rp.role_id
GROUP BY
    r.id,
    r.role_name,
    r.role_code,
    r.status,
    r.remark
```



但是：



不要机械复制这段 SQL。



请先检查当前数据库真实字段名，包括：


```text
role_name
role_code
role_id
permission_id
status
remark
deleted
```



等字段。



如果 \`sys\_role\` 存在：


```text
deleted
```



逻辑删除字段，则必须遵循当前项目已有逻辑删除规则，不应返回已经删除的角色。



如果当前表还有排序字段，例如：


```text
sort
sort_order
```



则可以按照现有业务规则排序。



如果没有明确排序字段，建议：


```text
ORDER BY id ASC
```



保证接口返回顺序稳定。
