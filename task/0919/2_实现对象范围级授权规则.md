请基于当前 CRM 项目，实现第一个对象/范围级授权规则：

SYSTEM_ADMIN 创建用户时，不能给新用户分配 SUPER_ADMIN 或 SYSTEM_ADMIN；
SUPER_ADMIN 保持现有的角色分配能力。

这是现有功能级授权之后的第一条业务范围授权，请保持最小修改。

【当前已有基础】

POST /api/users 已要求：

@PreAuthorize(
    "hasAuthority('user:create') and hasAuthority('user:assign_role')"
)

CreateUserRequest.roleIds 使用 @NotEmpty，
因此创建用户一定同时发生角色绑定。

JWT、SecurityUser、CustomUserDetailsService 已支持多角色和当前用户角色信息。

【本次目标】

只实现：
SYSTEM_ADMIN 不得在创建用户时分配 SUPER_ADMIN 或 SYSTEM_ADMIN。

普通业务角色目前包括：
SALES_MANAGER
SALES_STAFF

SUPER_ADMIN 暂不增加额外分配限制。

【第一步：先检查现有代码】

重点检查：

1. UserServiceImpl.createUser()
2. 当前 roleIds 如何查询和校验
3. SysRole / RoleMapper / RoleService 中是否已有根据角色 ID 查询 role_code 的能力
4. 当前 Service 如何获取当前登录操作者
5. 是否已有统一业务异常 / Forbidden 异常处理
6. 当前创建用户事务及日志位置

优先复用现有方法，不重复新增功能相同的 Mapper。

【第二步：实现】

在 UserServiceImpl.createUser() 的角色合法性校验之后、真正写入 sys_user_role 之前，增加操作者可分配角色范围检查。

规则：

1. 如果当前操作者具有 SUPER_ADMIN：
   保持现有行为，本次不增加新的目标角色限制。

2. 如果当前操作者具有 SYSTEM_ADMIN：
   如果请求 roleIds 对应角色中包含：
   - SUPER_ADMIN
   - SYSTEM_ADMIN

   则拒绝操作。

3. SYSTEM_ADMIN 分配：
   - SALES_MANAGER
   - SALES_STAFF

   应正常通过现有范围检查。

4. 不依赖前端传入的角色名称。
   必须根据服务端查询得到的真实 roleId → roleCode 判断。

5. 不因为用户同时拥有多个角色而只读取第一个角色。
   如果当前操作者同时具有 SUPER_ADMIN 和其他角色，应按 SUPER_ADMIN 的授权范围处理。

【职责要求】

Controller 的 @PreAuthorize 保持不变：
负责功能权限。

UserServiceImpl：
负责目标角色范围授权。

不要把 SYSTEM_ADMIN 的 roleCode 判断写到前端或 Controller 中作为唯一安全检查。

【异常处理】

如果项目已有合适的 403 业务异常体系，优先复用。

如果没有：
先分析当前全局异常处理方式，再采用最小方案，使“操作者无权分配目标角色”最终返回 HTTP 403。

不要把该场景错误处理成：
400 参数错误
401 未认证
500 系统异常

响应不得包含敏感信息或堆栈。

【测试】

至少覆盖：

1. SUPER_ADMIN
   + user:create
   + user:assign_role
   创建并绑定 SYSTEM_ADMIN
   → 范围授权通过

2. SYSTEM_ADMIN
   + user:create
   + user:assign_role
   绑定 SALES_MANAGER
   → 通过

3. SYSTEM_ADMIN
   绑定 SALES_STAFF
   → 通过

4. SYSTEM_ADMIN
   绑定 SUPER_ADMIN
   → 403
   → 不创建用户
   → 不写 sys_user_role

5. SYSTEM_ADMIN
   绑定 SYSTEM_ADMIN
   → 403

6. 多角色请求：
   SALES_MANAGER + SUPER_ADMIN
   → SYSTEM_ADMIN 整个请求拒绝
   不能只过滤掉非法角色后继续创建

7. 当前操作者拥有 SUPER_ADMIN + 其他角色
   → 不应因其他角色而被 SYSTEM_ADMIN 规则误拒绝

8. 原有 UserController / UserService 测试保持通过。

优先使用 Mock / 单元测试，不写真实数据库。

【限制】

本次不要实现：

- SYSTEM_ADMIN 修改角色权限限制
- SYSTEM_ADMIN 创建系统级角色限制
- 可分配权限集合
- 用户编辑功能
- 自身提权防护
- 前端角色选项过滤

不修改 JWT、SecurityUser、数据库结构。
不执行 Git commit。
